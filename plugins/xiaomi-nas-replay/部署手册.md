# 小米 NAS 录播回放插件部署手册

## 1. 前提和工作方式

- 小米 NAS 已能通过 SSH 使用 root 终端，系统具有 Python 3、Nginx、systemd 和原生插件中心。本插件不修改 SSH 设置。
- 现有 biliLive-tools fullstack Docker 服务正常运行，默认映射 `3000:3000`，已启用 `BILILIVE_TOOLS_PASSKEY`。
- 建议 Docker 镜像为 `ghcr.io/ailo-clark/bililive-tools:watch-progress-fullscreen-r1`，观看接口最低兼容 `watch-calendar-20261015`。旧版本缺少观看接口时，登录页会提示检查版本。插件本身不会拉取、启动、停止或改动 Docker 容器。
- 页面和静态资源随插件发布；接口走 `/plugin/<UID>/bililivereplay/api/...`，由 NAS Nginx 转发到 `http://127.0.0.1:3000/api/...`。请求保留 NAS 的 `need_reject` 访问检查及 Docker 密钥验证，不占用 NAS 自己的 `/api` 路径，不需要 `http_sub_module`。
- 插件仍通过 NAS App 现有的访问通道工作。公网速度和可用性受 NAS App 通道限制；本插件不创建新的穿透服务。

## 2. 一键安装

从 Release 下载插件 ZIP 和 `SHA256SUMS.txt`，将 ZIP 解压到 NAS 的普通目录。不要下载 Source code ZIP 代替安装包。安装包已包含构建后的前端。

进入解压目录，在 root 终端执行：

```sh
sh install.sh
```

首次安装会从 `/home/u*` 和 `/data/plugin/u*.list` 自动识别唯一用户。无法唯一识别时会在修改前停止，请明确指定数字 UID：

```sh
sh install.sh --uid 12345
```

用户 UID 可从现有 `/data/plugin/u*.list` 文件名或 `/home/u*` 用户目录查看。参数不带 `u` 前缀。Docker 使用其他映射端口时：

```sh
sh install.sh --uid 12345 --upstream http://127.0.0.1:3001
```

仅检查、不部署：

```sh
sh deploy/check.sh --uid 12345 --upstream http://127.0.0.1:3000
```

安装会校验包内文件、读取现有插件配置、备份、注册插件、添加限定插件路径的 API 代理，验证 Nginx 配置再重载。失败时自动撤销本次变更。它识别 overlay 映射到同一个底层文件的两份配置，只写入一次，并保留其他插件配置。

完成后完全退出并重新打开 NAS App，在「录播回放」登录。这里输入的是 Docker 的 `BILILIVE_TOOLS_PASSKEY`，不是 NAS 登录密码或账户加密密钥。密钥只保存在当前浏览器的插件专用存储项中，不写入发布包、部署备份或静态页面。

## 3. 使用

- 首页保留继续观看与主播卡片。选择主播后查看日历或场次列表。
- 点有录像的日期，手机显示底部面板，电脑显示弹窗。每场右侧的勾选图标可直接将整场全部分段标记已看；已看状态变灰，按钮带悬停提示。
- 整场标记保留每段已保存的位置和时长。操作使用现有逐段接口；网络失败时可能部分分段已完成，页面会重新读取实际状态，可重试。多页面进度冲突时停止覆盖并提示刷新。
- 点场次进入播放器，可选择分集或自动连播，保存及恢复观看进度。弹幕默认字号 16px、速度极慢，沿用共享播放器设置。
- 手机宽屏全屏在系统允许时请求横屏；系统拒绝时使用页面内旋转兼容方式。系统横屏能力仍取决于 NAS App 的 WebView。
- 顶部支持浅色、深色和自动主题；电脑与手机没有录制、上传或系统管理入口。

## 4. 升级与回退

下载新版安装包，解压到新目录，再执行 `sh install.sh`。脚本沿用已安装用户与上游端口，预检查新版，保存上一版包，升级失败时尝试自动恢复旧版。

安装后即使删除下载目录，恢复代码与备份仍保存在：

```text
/data/bililive-nas-replay/state.json
/data/bililive-nas-replay/backups/<备份编号>/
/data/bililive-nas-replay/releases/<备份编号>/
/data/bililive-nas-replay/runtime/
```

查看状态：

```sh
sh /data/bililive-nas-replay/runtime/status.sh
```

恢复到本次部署前：

```sh
sh /data/bililive-nas-replay/runtime/rollback.sh
```

首次部署的回滚会移除本插件并恢复原配置；升级后的回滚恢复上一版页面，插件仍可用。重复回滚是安全的。若需完全移除独立回放插件：

```sh
python3 /data/bililive-nas-replay/runtime/manage.py rollback
```

备份不会自动删除。不要在回滚前删除状态目录或手工覆盖 Nginx 的插件配置块；若检测到本插件配置被外部修改，脚本会停止并保留备份，避免覆盖后续人工修改。

## 5. 与原代理插件共存、数据和重启

新插件标识为 `bililivereplay`、数字 ID 为 109，状态目录为 `/data/bililive-nas-replay`。原代理插件 `bililivewatch` 及 `/data/bililive-nas-plugin` 独立保留，可以共存。二者连接同一个 Docker 后端，所以观看状态相通。

本插件不读写原 `app.db`，观看状态仍由 Docker 现有独立 `watch-history.db` 管理。不新增数据库、不改变原挂载、不删除录制历史或录像。回滚插件也不删除标记已看或播放进度，这些用户数据继续保留。

安装的 `bililivereplay-restore.service` 用于系统重启后恢复可能被 NAS 重建的插件入口；它不操作 Docker。NAS 固件升级若改变插件配置结构，检查会停止，此时请保留备份和错误信息。

## 6. 故障处理

- UID 不唯一：指定 `--uid`，不需要删除其他用户。
- 同名插件或 ID 已被其他插件占用：脚本停止，不覆盖现有插件。
- 接口连接失败：确认现有 Docker 映射端口，以及 `--upstream` 的 NAS 本机端口。
- 登录失败：检查 Docker 登录密钥、后端版本和当前服务；无需修改数据库。
- NAS App 未刷新入口：完全退出再打开，必要时查看 `status.sh`，避免重复手工编辑系统文件。
- `recovery_needed`：保留整个状态目录；先检查故障和备份，不要用旧配置整份覆盖共享配置。

测试覆盖模拟 NAS 文件系统的安装、失败回滚、升级回退、overlay 配置别名、重启恢复，以及真实 Nginx/后端/SQLite 的手机和电脑浏览器行为。没有小米 NAS 实机和真实 Android App 的最终验收结果，安装后应先用少量录像核对播放、横屏与公网通道。
