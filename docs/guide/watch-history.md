# 观看历史与手机观看页

播放录像时，程序每隔约 5 秒保存播放位置，并在暂停、拖动和页面进入后台时补存。再次打开同一录像可选择继续观看或从头播放。播放结束会标记为已看完，也可手动标记已看完或未观看。已看完的录像标题变灰，列表同时显示文字状态。

电脑和手机连接同一个后端时共享观看记录。当前使用同一份观看历史，不按登录密钥区分用户。直播流和剪辑工具中的预览不记录观看历史。

## 页面入口

- 电脑版菜单中的「观看历史」显示最近播放、观看中和已看完的录像。
- 手机登录后默认进入简洁观看页，也可直接打开前端地址的 `#/mobile`。
- 手机首页提供继续观看和最近录像；「录像」可搜索主播、房间号、标题并筛选观看状态；「文件」浏览已配置的录制目录。
- 手机页面只提供浏览、播放和观看状态操作。设置、上传、转码、录制管理和删除仍在电脑版。
- 「电脑版」和「手机观看页」入口可切换视图，浏览器会记住选择。

推荐在手机播放 H.264 视频、AAC 音频的 MP4。FLV、MKV、HEVC 等能否播放取决于设备和浏览器；TS 暂不支持直接播放。此功能不会自动转码或覆盖原文件。手机横屏和原生全屏也支持继续保存进度。

断网时会在当前浏览器暂存待同步的进度，重新打开录像或恢复网络后尝试同步。突然关闭浏览器或设备断电仍可能丢失最后几秒。两个页面同时播放同一录像时，较旧的更新会被拒绝，避免覆盖另一个页面保存的进度；看到冲突提示后重新打开录像。

## Docker 升级与数据保留

观看数据单独保存为 `/app/data/watch-history.db`，沿用 Docker 配置中的 `configFolder` 和既有数据挂载：

```yaml
volumes:
  - ./data:/app/data
```

无需新增 volume。本功能不扩展 `app.db` 或 `dm0.db` 的表结构，也不移动或修改录像。旧录像没有观看状态时显示为未观看。独立观看数据库包含自己的版本号，后续观看数据迁移只针对这个文件。

升级前，在电脑版导出备份，并保留当前镜像的标签或 digest。如果要复制整个数据目录，应先停止容器，再完整复制持久化目录（包括可能存在的 SQLite `-wal`、`-shm` 文件）；不要在服务运行中只复制 `.db` 文件。新版本通过 SQLite 备份 API 导出观看数据，包含已提交的 WAL 内容。

更新使用此代码构建的新镜像，重新创建容器时保留原来的数据挂载和录像挂载。前后端分离部署需要同时更新前端和后端；现有官方镜像不会自动包含本分支的改动。启动后检查：旧录制历史和配置仍可读取、`watch-history.db` 已生成、录像保存进度后重启容器仍能继续观看。

需要回退时使用原镜像和相同的数据挂载，保留 `watch-history.db`。旧程序不使用该文件，之后升级回来可以继续读取观看数据。其他版本本身对旧数据库的迁移不在本功能的兼容范围内；首次更新仍应在你当前版本的数据副本上演练。

## 备份与恢复

新的导出备份会同时包含 `app.db` 和 `watch-history.db`。导入新备份会恢复观看历史；导入缺少观看数据库的旧备份会保留当前观看数据。录像文件仍需单独保留。观看数据库版本不支持或文件损坏时，在修改现有数据前拒绝导入。

录制历史使用稳定的录像标识关联进度，临时播放 URL 过期或后端重启后可重新申请。文件浏览器中的独立视频使用路径和文件指纹区分文件；同路径文件替换后不会继承原进度。未纳入录制历史的文件移动或改名可能被视为新视频。

## 开发验证

在仓库根目录使用 `.node-version` 和 `packageManager` 指定的版本：

```bash
pnpm run build:base
pnpm --filter bililive-cli build
pnpm --filter biliLive-tools build:webui
pnpm --filter @biliLive-tools/shared exec vitest run test/watchHistory.test.ts
pnpm --filter @biliLive-tools/http exec vitest run test/watchHistory.test.ts test/watchBackup.test.ts
pnpm --filter biliLive-tools exec vitest run test/watchProgress.test.ts --environment node
```

测试覆盖独立数据库的持久化、旧数据库保持不变、冲突保存、观看状态重置、录像标识、文件替换、WAL 备份，以及鉴权、旧录制列表、分页和观看状态筛选。
