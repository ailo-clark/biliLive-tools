# 观看历史与手机观看页

播放录像时，程序每隔约 5 秒保存播放位置，并在暂停、拖动和页面进入后台时补存。再次打开同一录像可选择继续观看或从头播放。播放结束会标记为已看完，也可通过圆形勾选图标手动标记已看完或未观看，悬停显示操作提示。已看完的录像标题变灰，列表同时显示文字状态。

场次状态由全部分段汇总：全部看完才显示「已看完」，部分分段看完或已有播放进度时显示「观看中」，其余显示「未观看」，同时显示已看完 X/Y 段。新增分段会重新计入整场状态。没有直播 ID 时按主播和开播时间分组，缺少开播时间时分别展示。

电脑和手机连接同一个后端时共享观看记录。当前使用同一份观看历史，不按登录密钥区分用户。直播流和剪辑工具中的预览不记录观看历史。

## 页面入口

- 电脑版菜单中的「观看历史」显示最近播放、观看中和已看完的录像。
- 手机登录后默认进入简洁观看页，也可直接打开前端地址的 `#/mobile`。
- 电脑主播详情的「最近场次」直接显示整场观看状态，无需逐场进入查看。
- 手机首页提供继续观看和主播卡片；「录像」可切换按主播浏览和按场次搜索、筛选；「文件」浏览已配置的录制目录。
- 点击主播卡片进入录播日历，默认展示最近有录像的月份。日期格显示场次数，并用圆点、进度环或勾选标明未看、观看中或全部看完。点击日期查看当天全部场次，手机使用底部弹层，电脑使用弹窗。
- 主播日历支持场次列表视图。卡片上的「最近一场」和首页「继续观看」可直接进入整场播放器，已停用录制的主播仍保留历史入口。电脑版主播详情也可进入日历。
- 手机页面只提供浏览、播放和观看状态操作。设置、上传、转码、录制管理和删除仍在电脑版。
- 「电脑版」和「手机观看页」入口可切换视图，浏览器会记住选择。

推荐在手机播放 H.264 视频、AAC 音频的 MP4。FLV、MKV、HEVC 等能否播放取决于设备和浏览器；TS 暂不支持直接播放。此功能不会自动转码或覆盖原文件。手机横屏和原生全屏也支持继续保存进度。

断网时会在当前浏览器暂存待同步的进度，重新打开录像或恢复网络后尝试同步。突然关闭浏览器或设备断电仍可能丢失最后几秒。两个页面同时播放同一录像时，较旧的更新会被拒绝，避免覆盖另一个页面保存的进度；看到冲突提示后重新打开录像。

## 场次播放与日历

进入场次播放器后，默认选择最近播放的未完成分段；没有播放进度时选择第一段未看分段，全部已看完时从第一段开始。也可在分集列表中选择任意一段。每段仍使用原来的独立进度和观看标记，手动跳过的分段不会自动标记已看完。

自动连播默认开启，可通过播放器开关关闭，浏览器会记住设置。分段结束后先保存完成状态，再进入下一段；断网时保留待同步的完成标记。切换分段或返回页面前会补存进度。部分浏览器可能要求再次点击播放按钮，无法播放或已删除的分段会提示错误，可重试或选择其他分段。

日历按服务端配置时区（Docker 的 `TZ`）归档，兼容原历史中的秒／毫秒开播时间。跨午夜直播归到开播日并标注「跨日」。无录制记录不代表主播没有开播。日历汇总不扫描视频文件，播放时仍会校验原录像。

## Docker 升级与数据保留

观看数据单独保存为 `/app/data/watch-history.db`，沿用 Docker 配置中的 `configFolder` 和既有数据挂载：

```yaml
volumes:
  - ./data:/app/data
```

无需新增 volume。本功能不扩展 `app.db` 或 `dm0.db` 的表结构，也不移动或修改录像。`watch-mobile-20261013-r2` 首次启动时，会将已有录制历史中的视频、已配置录制／Webhook 目录内的独立视频默认标记为已看完；已经保存进度或手动标记过的视频保留原状态。目录扫描只读取元数据和前 64 KiB 文件指纹，视频较多时首次启动可能稍慢。

初始化只执行一次，结果和执行标记保存在独立观看数据库中；之后新增的视频默认未观看，重启不会重新批量标记。未在首次启动时配置或挂载的独立视频目录不会自动视为旧视频。独立观看数据库包含自己的版本号，后续观看数据迁移只针对这个文件。

升级前，在电脑版导出备份，并保留当前镜像的标签或 digest。如果要复制整个数据目录，应先停止容器，再完整复制持久化目录（包括可能存在的 SQLite `-wal`、`-shm` 文件）；不要在服务运行中只复制 `.db` 文件。新版本通过 SQLite 备份 API 导出观看数据，包含已提交的 WAL 内容。

更新使用此代码构建的新镜像，重新创建容器时保留原来的数据挂载和录像挂载。前后端分离部署需要同时更新前端和后端；现有官方镜像不会自动包含本分支的改动。启动后检查：旧录制历史和配置仍可读取、`watch-history.db` 已生成、录像保存进度后重启容器仍能继续观看。

需要回退时使用原镜像和相同的数据挂载，保留 `watch-history.db`。旧程序不使用该文件，之后升级回来可以继续读取观看数据。其他版本本身对旧数据库的迁移不在本功能的兼容范围内；首次更新仍应在你当前版本的数据副本上演练。

## 备份与恢复

新的导出备份会同时包含 `app.db` 和 `watch-history.db`。导入新备份会恢复观看历史；导入缺少观看数据库的旧备份会保留当前观看数据。录像文件仍需单独保留。观看数据库版本不支持或文件损坏时，在修改现有数据前拒绝导入。

录制历史使用稳定的录像标识关联进度，临时播放 URL 过期或后端重启后可重新申请。文件浏览器中的独立视频使用路径和文件指纹区分文件；同路径文件替换后不会继承原进度。未纳入录制历史的文件移动或改名可能被视为新视频。

## 开发验证

在仓库根目录使用 `.node-version` 和 `packageManager` 指定的版本：

```bash
pnpm run build:base
pnpm --filter bililive-cli build
pnpm --filter biliLive-tools build:webui
pnpm --filter @biliLive-tools/shared exec vitest run test/watchHistory.test.ts
pnpm --filter @biliLive-tools/http exec vitest run test/watchHistory.test.ts test/watchBackup.test.ts test/watchCalendar.test.ts
pnpm --filter biliLive-tools exec vitest run test/watchProgress.test.ts test/watchCalendar.test.ts test/index.test.ts --environment node
```

测试覆盖独立数据库的持久化、旧数据库保持不变、冲突保存、观看状态重置、录像标识、文件替换、WAL 备份，以及一次性初始化、手动标记保留、场次分组与完整场次分页、整场状态筛选和鉴权。
